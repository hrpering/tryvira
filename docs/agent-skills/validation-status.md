## Validation evidence

- Structural check: `python3 scripts/validate_agent_skills.py`.
- Offline checks: `python3 -m unittest discover -s skills/evals -v` (structural behavior assertions, public contract cross-checks, an isolated Node mock fixture, and a ZIP packaging test).
- The 66-row trigger corpus has one positive, negative, and ambiguous prompt per skill; a separate 25-row synthetic workflow corpus covers surface gaps (including Vercel AI streaming), authority, asynchronous Pack completion, security, evaluation, and recovery. The exporter maps positives/negatives to Anthropic `run_eval.py` input and keeps ambiguities separate. One isolated Codex CLI evaluation on `vira-signals` completed a positive trigger case, selecting the GitHub-installed skill, producing a plan that preserved synthetic-evidence and missing-consent/scope limits without API calls. A negative generic-Python task did not select/use the skill and its separately run two unit tests passed. An ambiguous dashboard question elicited a clarification and no API call; skill selection itself was not observable. A later explicit multi-skill Codex run read `vira-get-started`, `vira-integrate-app`, `vira-js-sdk`, and `vira-framework-integration`, implemented a Vercel AI SDK streaming route against the installed JavaScript SDK, and passed six stubbed handler tests plus a Next.js build after correcting an initial failing test run and TypeScript error. The task explicitly listed the skills, so this is workflow execution evidence, not automatic trigger accuracy. Its exact prompt, model/CLI, package version, initial failures, and final result are recorded in `skills/evals/model-runs.jsonl`. These individual probes are qualitative, not a measured success or accuracy rate; the full corpus has not been submitted to a model evaluator.
- An additional automatic-trigger probe attempted `vira-js-sdk` from one natural-language positive prompt in an isolated read-only project. Codex CLI failed to initialize the app-server with `Operation not permitted` before model invocation, so the attempt is logged as `not_run` and excluded from results. Anthropic `run_eval.py` could not run because its required `claude` executable is absent.
- `npm run verify` runs the repository security/contract scan, structural skill validation and 28 local skill tests, MCP catalog checks, and the lifecycle tutorial mock suite. GitHub Actions runs it on PRs and main pushes.
- The Next.js app builds and its fourteen tests pass, including Vercel AI SDK streaming with active, unavailable, malformed, error, missing-input, request-correlation and idempotency-key cases, plus the deeper SDK candidate-to-Pack Revision wire-contract, digest-binding, authority-diff, and approval-gate fixtures. The production route is server-only, checks required Vira/OpenAI configuration, and compiles against installed published `@tryvira/sdk` 0.1.43 types. The MCP host fixture performs initialize and dynamic tool discovery; FastAPI has seven passing tests; LangGraph has four passing graph tests. The FastAPI suite includes a no-network wire-contract test against the installed published Python SDK 0.1.43 artifact. Vira/model calls use fixture interfaces, so they do not call Vira or a model provider. Container image builds remain unverified because the local Docker socket denied access.
- All ten marketing tutorial scripts ran, using the installed published JavaScript SDK 0.1.43, against a loopback-only fake Vira HTTP service. The two tutorial tests passed after the fixture exposed a missing idempotency key on `evaluateQuality`; the tutorial now supplies a run-bound key. The mock covers queued 202 installation/materialization polling, SDK wire bodies, evaluation-to-Pack digest binding, install/release/Teach approval gates, stale digest/evaluation rejection, and approval-before-release ordering. Fixture PASSED/evaluated states are synthetic and are not Vira evidence. CI installs the tutorial lock and runs this suite. This test does not validate backend authorization, provider evaluation, or Studio behavior.
- A read-only source-of-truth cross-check found that Python `resolve_runtime` must not be treated as returning JavaScript projection fields. FastAPI and LangGraph now call `serve_behavior_projection` and consume its `body.projection`; the installed artifact's exact outgoing path, request body, and idempotency header are checked with a stub transport. No production file was changed and no live Vira call was made.

- The local skill-library suite has 28 passing tests. It checks skill structure, public contracts, the complete method-inventory snapshot, and deployment/license boundaries; it does not run an AI assistant against all skills, so trigger accuracy and execution success rates remain unmeasured.
